### Operations implementation contract

- `lib/operations/status.ts` exports `assertProductionIntakeAllowed(env?)`, `productionIntakeBlockers(env?)`, `inspectOperationsConfiguration(env?)`, `verifyHostingerMailMetadata(args?)`, `collectOperationsStatus(args)`, and `redactOperationsDiagnostic(value)`. The verifier calls only documented `GET https://api.mail.hostinger.com/api/v1/me` with a bounded timeout. It accepts HTTP 200 only after confirming the configured authorized mailbox resource ID, maps an actual 403 to safe code `MAIL_HTTP_403`, returns `checkedAt`, and never returns an address, token, body, or provider error text.
- `GET /api/operations/status` requires `requireAdvisor`, sets `Cache-Control: no-store`, and returns `{status}` with boolean configuration gates, provider verification/checkedAt, and aggregate `outbox:{pending,failed}` only. It deliberately makes no production-operational claim. A database failure yields null aggregate counts rather than an error payload.
- `POST /api/operations/dispatch` is scheduler-authenticated with `x-operations-timestamp`, `x-operations-nonce`, and `x-operations-signature`. Signature is HMAC-SHA256 of `timestamp.nonce.POST./api/operations/dispatch`; timestamp TTL is five minutes and nonce fingerprint consumption is one-time. Memory replay is test/development only. Production returns 503 until an atomic durable replay store is applied. It calls parent-owned `deliverDueReports(limit=2)` to create private queued PDFs but never delivers them by email. Outbound email remains 423-held until `OPERATIONS_OUTBOX_DISPATCH_APPROVED=true`; only then may it call the durable outbox worker.

The parent-owned report queue is integrated through `deliverDueReports(limit=2)`; operations must not create a replacement.
- Production intake parent wiring must call `assertProductionIntakeAllowed()` at final submit only when `NODE_ENV==='production'`. Required explicit gates are real-client approval, compliance approval, private encrypted storage, valid encryption key, report-download signing, restore-test approval/date, six-year retention and legal-hold policy approvals, DB, HTTPS `APP_ORIGIN`, and Hostinger runtime configuration. Non-production intake is not disabled.

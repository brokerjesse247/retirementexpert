## Authentication

GET /api/auth/session -> {advisor:null|{id,name,email},csrfToken:string|null,twoFactorEnabled:boolean}. POST /api/auth/login {email,password} -> {requiresTwoFactor:true,enrollmentRequired:boolean,csrfToken:string}; credentials verified, challenge cookie only (not advisor session). GET /api/auth/enroll -> {secret,uri,qrDataUrl,csrfToken} only password-verified enrollment challenge. POST /api/auth/enroll {code,csrfToken} -> {ok:true,recoveryCodes:string[]} and real session after verified enrollment. POST /api/auth/verify {code,csrfToken} accepts TOTP or recovery, creates real session. POST /api/auth/logout {csrfToken}. POST /api/auth/forgot {email} generic response {ok:true} no enumeration; reset email outbox. POST /api/auth/reset {token,password} -> {ok:true}; reset token comes via URL fragment and UI POST only. Reset invalidates sessions. GET session not auto-provision. CLI scripts/create-advisor.ts requires explicit env inputs, creates one advisor without unsafe public signup or printed password. No dev auth bypass.

## Drafts and uploads

GET /api/intake/draft -> {data:IntakeData,step:number,revision:number,submitted:boolean,csrfToken:string}, existing session only else404. POST /api/intake/draft {} creates new if absent -> same shape; creation safe with origin validation. PATCH /api/intake/draft {data,step,revision,csrfToken} -> same shape, optimistic conflict409. POST /api/intake/resume {email,csrfToken} emails resume to saved matching email only, active draft session required -> {delivery:'queued'|'sent'|'failed',message:string}, never expose tokens. POST /api/intake/resume/exchange {token} -> {ok:true}, hashed expiring one-use grant exchanges into draft session. /intake/resume#token=... page strips fragment and POSTs token then routes /intake. POST /api/intake/submit {data,revision,csrfToken} full intakeSchema validation/consent required -> {ok:true,clientId:string,emailDelivery:'queued'|'sent'|'failed'}, idempotent per draft. Consent schema checkbox data.consent true with backend consent timestamp/version. Honeypot data.website must empty. Validation server and client.

POST /api/intake/upload multipart file+csrfToken -> {id,name,size}; draft auth required, allow PDF only max5MiB strict file signature/type/name validation; data may include ssaUploadId. GET /api/intake/upload -> {upload:null|{id,name,size}}. After submit client ownership attaches upload. Advisor GET /api/clients/:id/upload -> {upload:null|{id,name,size}}; POST same path {csrfToken} -> {downloadUrl} signed token query short expiry no PII; GET /api/uploads/:id?token=... checks signed expiry + same advisor owner, returns PDF attachment no-store. No public unprotected file route.
